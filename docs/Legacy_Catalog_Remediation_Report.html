Production Readiness: GO — All P1 fixes applied. 655/655 tests pass. TypeScript clean across api/web/admin. No database columns dropped. No breaking changes to orders or cart.

1. Executive Summary

This remediation enforces the canonical catalog architecture where MOQ, availability, and pricing belong on merchantOffers, not on the products table. It eliminates the legacy dual-write paths that allowed the Old Product Editor and merchant category CRUD to bypass the governed offer layer.

  • 7 work groups executed across backend, frontend (merchant + admin), search, and tests
  • 14 files modified, 2 files created
  • 0 database columns dropped — all legacy columns retained for historical data
  • 655 tests pass (including 9 new security tests)

10. Remaining Items & Future Work

  • Product Studio Edit Mode — Currently create-only. When edit mode is added, it should operate on product fields only (not offer fields). Offer editing is a separate flow via createMerchantOffer() / updateMerchantOffer().
  • Column Removal Migration — After a suitable cooldown period (e.g., 90 days), a migration can drop products.moq, products.isAvailable, and products.attributes once confirmed no code reads them.
  • Offer MOQ on Product Cards — Currently cards resolve pricing at qty=1. A future enhancement could display the cheapest offer's MOQ alongside the price, fetched from the offer layer.
  • CSV Import MOQ Handling — Import currently ignores MOQ. Future work could parse offer-level MOQ from CSV and create/update offers accordingly.
  • Mobile App Verification — Mobile already uses the new architecture (offer layer). No changes needed, but end-to-end verification on mobile is recommended before production deployment.
