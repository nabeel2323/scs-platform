## Purpose and evidence boundary

This inventory is derived from the Drizzle schema modules re-exported by apps/api/src/drizzle/schema.ts on the reviewed branch. The current source contains **100 Drizzle table declarations across module schema files**. The `schema.ts` barrel re-exports 98 of them; `catalog_imports` and `catalog_import_errors` are defined in `catalog-import.schema.ts` but that file is not re-exported by the barrel. This matrix now includes all 100 source declarations, including the exported `payment_proof_upload_intents` table.

It is not the complete live database inventory. The detailed 19-November catalog report and 21-November reconciliation recorded 114 public relations and historically described this as 99 Drizzle declarations plus 15 non-Drizzle/partition relations. Current source review finds 100 Drizzle declarations across module schema files, of which 98 are re-exported by `apps/api/src/drizzle/schema.ts`; the matrix previously included the two non-barrel catalog-import tables but omitted `payment_proof_upload_intents`. Therefore the historical 99+15 split is not a current source-backed reconciliation. A separate 116 count remains unresolved. Keep the 114 and 116 counts as historical evidence only and refresh the protected read-only catalog before asserting any live total or delta. Raw-SQL-only tables, extensions, partitions, views, or objects in other schemas may not appear in the Drizzle export.

The scope descriptions below are candidate row-ownership models, not verified direct column predicates. They must not be translated mechanically into policies. Exact owner columns, foreign-key paths, route/service operations, worker access, and write semantics still require source and migration inspection.
