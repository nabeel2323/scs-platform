1. Access & Signing In

The platform has three surfaces. Which one you use depends on your role:

SurfaceWho it's forHow to open it
WebBuyers (retailers) and Merchants (wholesalers)Browser at the web app URL (dev http://localhost:3100)
MobileBuyers and Merchants on the go; Drivers (Phase 2)Flutter app (retail / wholesale flavor)
AdminPlatform operations staffBrowser at the admin console (dev http://localhost:3200)

1.1 Two ways to sign in

Everyone signs in with a phone number. You can use a one-time passcode (OTP), or set a password for faster sign-in on devices you trust.

OTP sign-in

  1. Enter your phone number and request a code.
  2. Enter the 6-digit code (in dev the code is delivered to the console/Redis, not SMS).
  3. You're signed in; this device becomes trusted.

Password sign-in

  1. After your first OTP sign-in, open Profile → Credentials and set a password.
  2. Next time, sign in with phone + password on a trusted device — no OTP needed.
  3. On a new device you'll be asked for one OTP step-up, then it's trusted too.
Device trust

Your sessions are listed under Profile → Sessions, where you can review active devices and sign out remotely. Access tokens refresh automatically in the background.

1.2 Choosing your role

On first registration you pick a track: "Sell wholesale" (Merchant) or "Buy for my store" (Buyer). This sets your onboarding flow and home experience. You belong to an organization; merchants can invite staff with a join code.

2. Merchant / Wholesaler

Mental model: a command centre of queues and SLAs. Web carries the bulk work (catalogue, pricing, imports); mobile carries alerts, quick order acceptance and scanning. Your hero action is accepting an order in three taps from a push notification.

Top navigation: Today · Orders · Catalogue · Inventory · Pricing · Promotions · Customers · Analytics

2.1 Onboarding & verification (activation)

(name/type)"] --> D["Store wizard

  1. Create your organization — name, type, optional tax ID (you can add it later). WebMobile
  2. Run the store wizard — business info, location pin + service radius, categories & brands. Steps autosave; exit and resume anytime.
  3. Upload KYC documents — the required document set is configured per market; each upload shows progress and can be retried.
  4. Submit for verification — you'll see a status timeline (Submitted → In review → Decision) with an ETA (review SLA is 48h).
  5. Reach activation — the checklist tracks Verified → Products (target ≥20 SKUs) → First order. The primary call-to-action offers three ways to add products: manual, Excel/CSV import, or concierge (ops imports for you).
Where

Web: /merchant/register, /merchant/onboard, /merchant/success. Mobile: the merchant registration screen and the Merchant Dashboard hub (/merchant).

2.2 Catalogue management

Web /merchant/catalog · Mobile Merchant Dashboard → Catalogue

  • Catalogue grid — filter by Draft / Active / Low stock / Rejected; inline stock edit; bulk activate, archive, duplicate.
  • Product editor — three tabs: Basics, Packaging & Pricing, Media. Drafts autosave. Barcode scan prefills name/brand. "Duplicate product" and "copy pricing from…" accelerate entry.
  • Variants — add SKUs per product (size/unit/barcode/weight).
  • Media — upload images (presigned upload) or attach by URL.
  • Categories — create/edit name, Arabic name and description; delete when unused.

Bulk import (Excel/CSV)

flowchart LR U["Upload file"] --> M["Column mapping
(auto + override)"] --> V["Validation report
(row-level errors)"] --> P["Import progress"] --> R["Publish review"]

The importer auto-maps columns, lists row-level errors (missing price, bad category, duplicate SKU) with a downloadable corrected template, and runs asynchronously. Re-importing the same SKU updates the existing product (idempotent by SKU). Nothing goes live unreviewed. Web /merchant/import.

2.3 Pricing & quantity tiers

Web /merchant/pricing

  • Create price lists and add quantity tiers as rows (min qty → unit price). A live preview shows the buyer-facing ladder.
  • Set the MOQ (minimum order quantity) per product/variant with validation.
  • Phase 1 supports PERCENT, FIXED, QTY_DISCOUNT and TIME_LIMITED discount types.

2.4 Inventory / stock

Web /merchant/inventory

  • View stock per warehouse; adjust quantities with a reason (recorded as a stock movement).
  • Low-stock alerts derive from each item's reorder point and appear on your Today home.
  • Stock is reserved automatically when you accept an order and released on cancellation or partial acceptance.

2.5 Order acceptance (hero flow)

flowchart LR N["Push: New order
14 items · 2,340.00"] --> D["Order detail
stock + price-delta guard"] D --> AA["Accept all"] & AP["Accept partial"] & RJ["Reject (reason)"] AA --> PR["PREPARING"] --> RD["READY"]
  1. Open the order from the notification or Orders queue. Each line shows qty, snapshot price and current stock.
  2. If your price list changed since checkout, a price-delta guard flags the lines — confirm each changed line explicitly (protects your margin).
  3. Choose Accept all, Accept partial (item-level toggles + editable confirmed quantities; the rest releases automatically), or Reject (reason mandatory).
  4. The buyer is notified automatically. Move the order to Ready when packed; for pickup, a handover code is generated.

Web /merchant/orders · Mobile Merchant Dashboard → Orders. An SLA countdown (amber → red) shows time left to respond; the default confirmation SLA is 12 hours.

2.6 Customers, store profile & organization

Customers

Web /merchant/customers · Mobile
Your buyer list with revenue, order count, last order and average order value; search and sort.

Store profile

Web /merchant/store · Mobile
Edit display name, description, currency, locale, timezone, city and warehouses. Slug and verification status are read-only.

Organization

Web /merchant/organization · Mobile
Edit org details, view members, add/remove staff, and switch active organization if you belong to several.

Coming later

Promotions exist in the backend and buyers can enter a promo code in the cart, but there is no merchant-facing promotions screen yet, and the discount is not applied to order totals at checkout (a known Phase 1 gap, tracked as API-B4). Merchant analytics dashboards arrive in Phase 5.

3.1 Home & discovery

Web /

The home screen is a launcher with primary actions — Search Products, Browse Stores, Cart and My Orders — plus quick links to Notifications, Reviews & Disputes, merchant registration and sign-in.

Planned

The richer “Restock Suggestions” / Smart Reorder home (saved suppliers, offers nearby, predicted replenishment) is a Phase 4–5 feature and is not yet live.

3.2 Search & browse

Web /search · /stores

  • Search by name, SKU or barcode; results update as you type (debounced).
  • Filter by Category (with product counts) and Brand, or tap a category chip. A live result count is shown.
  • Each product card shows the image, title and MOQ, with a + Cart quick-add that picks the product's default variant.
  • Browse Stores lists wholesalers; open a store to see its verification badge and product grid.

On web, filters are currently category + brand. Price/MOQ/distance/rating filters, sponsored slots, compare-across-suppliers and barcode scanning are mobile / later-phase items.

3.3 Store & product pages

Store page

Web /stores/[slug]
Store header (logo, name, description, verification status badge) and its product grid with add-to-cart.

Product page

Web /products/[id]
Image, English + Arabic title, availability and MOQ badges, description, and a variant list. Set a quantity (minimum = MOQ) and Add to Cart per variant.

3.4 Cart

Web /cart

  • Items are grouped by supplier, each group with its own header; adjust quantities with the −/+ steppers, remove a line, or clear the cart.
  • Enter a promo code and press Apply — the code is stored on the cart.
  • A single Total is shown; proceed to checkout when ready.
Known gap

An applied promo code is recorded, but the resulting discount, delivery fee and VAT are not yet added into the order total at checkout (API-B4). The total you see is the sum of line subtotals.

3.5 Checkout & payment

Web /checkout

  1. Enter the delivery address (required) and city.
  2. Choose a fulfillment method: Platform Delivery, Merchant Delivery, or Pickup.
  3. Add optional notes / special instructions.
  4. Press Place Order. The request is protected by an idempotency key, so a double-tap won't duplicate the order. You're taken to My Orders.
No payment gateway yet

Phase 1 orders are placed on account — there is no card/wallet step. Online payments and cash-on-delivery settlement arrive in Phase 3.

3.6 Orders, tracking, cancel & reorder

Web /orders · /orders/[id]

  • The order list shows every order with its status; open one for the detail view.
  • Order detail lists items (with any confirmed quantity if the merchant partially accepted), a financial breakdown, and an Order Timeline of status history.
  • Cancel is available while an order is early (Submitted, Accepted, Partially Accepted, Preparing, Ready) and requires a reason.
  • Reorder appears once an order is Delivered or Completed — one tap refills your cart.

3.7 Favorites, reviews & disputes

Favorites

Web /favorites
Your saved products; open or remove each. (Saving is driven from the mobile app / API in Phase 1.)

Reviews

Web /reviews → Write a Review
Provide the Order ID, subject (Store/Driver/Buyer) ID, a 1–5 star rating and a comment.

Disputes

Web /reviews → Open a Dispute
Provide the Order ID, a reason and a description; ops triages it in the admin console.

Reviews and disputes currently ask you to paste the Order/Subject IDs. Order-gated pickers (rate straight from a delivered order) are a planned refinement.

3.8 Notifications

Web /notifications · Mobile push

A chronological list with unread highlighting, channel and type badges. Tap to mark as read, or use Mark All Read. Transactional updates (order placed, accepted, out for delivery, delivered) also arrive as mobile push where a device is registered.

3.9 Account & security

Web /account · /profile/credentials · /profile/sessions

  • Profile — edit full name, email and locale (English / العربية); phone, status and user ID are read-only.
  • Organizations — see the organizations you belong to, your role, and any invite code to share with staff.
  • Security — set an email/password (/profile/credentials) and review or revoke active sessions (/profile/sessions).
  • Devices — push-notification devices are registered from the mobile app.

5. Platform Admin

Mental model: an operations console — queue-centric, evidence-rich, and audit-logged. Every governance action (verify a merchant, moderate a product, resolve a dispute) writes to the audit trail.

Admin dev http://localhost:3200 · Top navigation: Overview · Verifications · Merchants · Users · Products · Categories · Orders · Disputes · KPIs · Audit

5.1 Sign-in & permissions

Admin /auth/login

Staff sign in with email/phone + password; a device-trust check applies on new devices. Access is role-based — SUPER_ADMIN, ADMIN and MODERATOR roles gate which screens and actions you can use. If an action returns 403 Forbidden, your role lacks the required permission (see FAQ).

5.2 Overview dashboard

Admin /

A KPI strip — Total Users, Verified Merchants, Pending Merchants, Total Orders, Revenue (SAR), Completion Rate — above quick-access cards to User Management, Order Monitor, Merchant Directory, Verification Queue, KPI Dashboard and Audit Log.

5.3 KPI dashboard

Admin /kpis

  • Pick a date range and Apply.
  • Revenue & orders: total revenue, orders, completed, cancelled/rejected, completion & cancellation rates.
  • Conversion: users, verified/pending merchants, first-order rate, repeat-order rate.
  • Activation funnel: Registered → Verified → Catalog ≥ 20 → First Order → Repeat ×3, with step-to-step conversion and an overall activation rate.

7. FAQ & Troubleshooting

Where's my OTP code in development?

In dev, one-time codes are written to the API console / Redis (key otp:<phone>), not sent by SMS. In production they go via SMS/WhatsApp.

Why doesn't my total include discount, VAT or delivery?

Checkout currently sums line subtotals only — promotions, 15% VAT and delivery fees are a known Phase 1 gap (API-B4) and are not yet applied to totals.

I get 403 Forbidden in the admin console.

Your role lacks the required permission key. After any permission/seed change, sign out and back in so your token carries the updated claims; otherwise ask a SUPER_ADMIN to grant the permission.

The mobile app can't reach the API.

On a physical device, point API_URL at your PC's LAN IP (not 10.0.2.2, which is emulator-only), ensure the API firewall rule allows inbound on the network profile, or use adb reverse tcp:3000 tcp:3000.

When can I cancel or reorder?

Cancel is offered while an order is early (Submitted → Ready) and needs a reason. Reorder appears once an order is Delivered or Completed.

My session keeps expiring.

Access tokens are short-lived (15 min) and refresh automatically. On a new device you'll do a one-time OTP step-up before it becomes trusted; review devices under Profile → Sessions.

Where are payments and the driver app?

Payments are Phase 3; last-mile delivery/driver is Phase 2. Phase 1 orders are on account and fulfilled by merchant delivery or pickup.

Can I switch between Arabic and English?

Yes — set your locale under /account. Product Arabic titles render right-to-left where provided.

Need help?

Use Reviews & Disputes (/reviews) to raise an order issue, or contact platform support through the admin operations team. Include the Order ID for fastest resolution.
