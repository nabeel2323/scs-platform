1. Inventory Management

Page: apps/web/src/app/merchant/inventory/page.tsx (233 lines). API: inventory.controller.ts (89 lines).

Current Capabilities

  • Warehouse selector, item table (qty on hand / reserved / available / reorder point)
  • Stock adjustment dialog via POST /v1/inventory/adjust
  • Low-stock inline count in header
  • API also: GET /v1/inventory/:id/movements, PATCH /v1/inventory/:id, GET /v1/inventory/low-stock

Gap Register

IDPriorityGapEffort
INV-1P0No stock movement history. API returns movements but UI never calls it.1d
INV-2P1No dedicated low-stock alerts page/filter. Count shown but cannot isolate items.1d
INV-3P1No item search/filter. Large warehouses scroll unfiltered table.0.5d
INV-4P1No inline reorder point editing. PATCH /v1/inventory/:id exists but unused.0.5d
INV-5P2No bulk adjustment. Each row requires separate dialog.1d
API Coverage

All P0/P1 gaps are UI-only. The API already supports movements, variant lookup, reserve/release, and item updates.

3. Product Images

Gap Register

IDPriorityGapEffort
IMG-1P0No image upload UI in product editor. Text field for URLs only. Merchants cannot add photos.2d
IMG-2P0No image replace/remove. Once stored, references are permanent. No delete endpoint or UI.1.5d
IMG-3P1Single image display only. No gallery or carousel. Products with multiple images waste the rest.1d
IMG-4P2No image reordering. Cannot set primary image order.0.5d

Activation Dependency

Verification approval requires productImageCount > 0. Without upload UI, merchants cannot satisfy this independently. Launch blocker for self-service onboarding.

10.2 Rollback Procedures

ChangeRollback
Brand API additionsRemove new routes; no schema change.
Search API filter paramsAdditive; old clients unaffected.
Pricing CRUD UIUI-only; revert to read-only page.
Image upload UIUI-only; revert to text field.
Navbar responsive menuCSS/component only; revert to flex.
Mobile screensRemove new files and route entries.
Key Principle

All gaps are additive. No schema migration, API contract break, or data mutation required. Every phase deploys independently and rolls back by reverting affected files.
