# M7.2.3-C — Production Carrier Operations & Reconciliation

## Overview

M7.2.3-C hardens the SCS carrier subsystem for production operating conditions.
It adds atomic outbox claiming, crash recovery, circuit breaker protection,
reconciliation for uncertain carrier states, tracking event safety, webhook
async retry, admin recovery endpoints, and comprehensive observability.

## Key Design Decisions

- **No new infrastructure**: Uses existing PostgreSQL, NestJS workers, outbox pattern.
- **FOR UPDATE SKIP LOCKED**: PostgreSQL-native concurrent claiming without external lock service.
- **In-memory circuit breaker**: Single-process NestJS; per-provider+environment scope.
- **Status progression**: Explicit ordered array prevents backward transitions.
- **Webhook retry via outbox**: Reuses existing worker infrastructure.
- **RECOVERY_REQUIRED**: Never blindly retry uncertain timeouts.

## Configuration

| Env Var | Default | Purpose |
|---|---|---|
| `CARRIER_RETRY_INITIAL_DELAY_MS` | 30000 | Initial backoff delay |
| `CARRIER_RETRY_MAX_DELAY_MS` | 3600000 | Maximum backoff cap (1h) |
| `CARRIER_RETRY_MAX_ATTEMPTS` | 8 | Max retry attempts before dead-letter |
| `CARRIER_CB_FAILURE_THRESHOLD` | 5 | Consecutive failures to open circuit |
| `CARRIER_CB_COOLDOWN_MS` | 60000 | OPEN → HALF_OPEN cooldown |
| `CARRIER_CB_SUCCESS_THRESHOLD` | 1 | Successes in HALF_OPEN to close |
| `CARRIER_TRACKING_POLL_INTERVAL_MS` | 600000 | Tracking poll interval (10min) |
| `CARRIER_RECONCILIATION_INTERVAL_MS` | 600000 | Reconciliation cycle (10min) |
