7. Suggested Remediation Order

Principle: fix the gaps that unlock the most user value with the least risk and fewest dependencies first. All P1 items can be done in parallel by different team members.
OrderTaskPriorityEffortRationaleTesting StrategyRiskSprint
1 Reorder button P1 2 SP Backend exists. Pure UI wiring. Zero risk. Highest user-value-per-effort for B2B repeat ordering. E2E test: complete order → click reorder → verify cart populated. Unit test: reorder service logic (already exists). Very Low Week 1
2 Database backup script P1 2 SP Infrastructure only. No code changes. Required for launch readiness standard §21.6 Security. Run backup → verify dump file → restore to fresh DB → verify data integrity. Document runbook. Very Low Week 1
3 Customer list P1 3 SP Read-only aggregation query. No writes to existing data. Wholesaler relationship management. Integration test: create orders from 2 buyers → verify customer list returns 2 entries with correct counts. API contract test. Low Week 1

5 Address book P1 5 SP Highest effort P1. New table + CRUD + UI. Reduces checkout friction for repeat buyers. Integration test: CRUD addresses. E2E: save address → checkout → verify pre-filled. Mobile test: address management. Medium (schema migration) Week 2

11. Conclusion & Recommendation

Recommendation: Proceed to pilot launch with current codebase.

The codebase satisfies all P0 launch-blocking requirements from §29.1 and meets 6 of 7 launch readiness standards from §21.6. The single readiness gap (automated backups) is an infrastructure task that can be completed in parallel with pilot preparation.

The 5 P1 functional gaps (reorder UI, customer list, saved suppliers, backups, address book) total 15 story points and can be closed within 1.5 weeks of development. None of them prevent a controlled pilot with anchor merchants and a pilot retailer group as described in §35.1–35.2.

Suggested path:
1. Deploy backup script immediately (Week 1, Day 1)
2. Wire reorder button (Week 1, Day 1–2)
3. Build customer list endpoint + page (Week 1)
4. Extend favorites to support saved suppliers (Week 1–2)
5. Build address book (Week 2)
6. Begin pilot with anchor merchants while P1 fixes are deployed
7. Close P2 items (category UI, operations dashboard) in Week 3–4
